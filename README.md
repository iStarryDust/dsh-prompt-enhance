# 增强提示词（prompt-enhance）

发送框"发送消息"按钮左侧的星形按钮：单击把输入框草稿单轮重写为更清晰的提示词（跟随会话当前模型，不读会话历史，附件不受影响）；重写后按钮变为"恢复原文"，再点恢复原稿；重写进行中点击 = 取消（原文不动）。

## 安装

```sh
dsh plugin add @istarry/dsh-prompt-enhance
```

装完重启 DSH 服务。

## 两个模板的区别

一次增强 = 一次单轮 LLM 调用，两个模板对应这条调用的两个角色：

- `system-template.md`（系统模板）——**重写规则**，每次调用固定下发：告诉模型"你是提示词工程专家、怎么改写、语言跟随、≤800 字符"等。改它 = 改"怎么改"。
- `user-template.md`（用户模板）——**请求包装**，随每次请求携带草稿。改它 = 改"草稿怎么交给模型"。

两份内容都可自由编写，不必遵循任何格式：

- `{input}` 占位符**可有可无**——保留时草稿插入该位置；不保留时草稿自动附在模板末尾（空行分隔）
- 唯一不能做的是把文件存成空的（空文件视为"没有文件"，回退内置默认）

## 模板位置（自动安装）

模板在**首次使用时自动从插件内置默认播种**到 Harness 主目录：

```
C:\Users\<你>\.dsh\prompt-enhance\prompts\
├── system-template.md
└── user-template.md
```

- 直接改这里的文件，下一次增强立即生效，无需重启
- 已有文件不会被覆盖（你的修改优先）；删除文件即回到内置默认
- 设置页"恢复默认模板"会把默认值写回这两个文件

插件目录里的 `prompts/` 只是出厂默认，随插件分发，用于首次播种。

## 结构

- `cordis.patch.yml` — bundle 三行：宿主服务 `prompt-enhance`、composer 按钮 `ui-prompt-enhance`、设置页 `ui-settings-prompt-enhance`
- `prompts/` — 出厂默认模板（播种源）
- `packages/` — 三个插件包的发布产物（file: 依赖源）
- `node_modules/` — 运行时闭包（vendor.mjs 生成）
- `vendor.mjs`（上级目录）— 从构建工作区重新同步产物的脚本

## 设置页

设置 → 增强提示词：显示开关、覆盖模型（provider/model，留空跟随会话）、温度、输出上限，以及两个模板的就地编辑器（与直接改文件等效）。
